# Product Principles

## 1. Automation Should Be Reusable

Avoid solving each customer problem with a custom implementation.

## 2. Complexity Should Be Hidden Where Possible

The platform may be technically complex, but users should not need
to understand the underlying architecture.

## 3. Automation Must Be Observable

Users need to understand what happened and why.

## 4. Failure Is a Product State

A failed workflow should provide enough information to diagnose the problem.

## 5. Extensibility Is a First-Class Capability

New integrations, triggers and actions should be possible without
redesigning the entire platform.

## 6. Safety Before Automation

Automation should never silently perform an action that the user
did not understand or authorize.
